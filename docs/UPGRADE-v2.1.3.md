# Epusdt v2.1.3 升级说明

本插件对接 Epusdt 的 EPay 兼容接口。本轮对照官方 `v2.1.3` 标签、提交 `2e4ef464bf16fd9f1073071e6b364c3a8cb586de` 的控制器、签名、订单回调及测试进行核对。

## 本次修正

| 优先级 | 原有问题及影响 | 修正 |
| --- | --- | --- |
| 高 | cURL 关闭 HTTPS 证书和主机名校验，无法验证网关身份 | 开启证书链及主机名校验，限定 HTTP / HTTPS，增加连接超时 |
| 中 | 回调没有检查 PID、非空网关流水号；浮点四舍五入会接受多余小数或非数字后缀 | 检查必要字段及数字 PID，用十进制字符串精确比较金额，拒绝异常参数和错误签名算法 |
| 中 | 请求没有声明订单法币，网关修改默认法币可能改变相同金额的含义 | 增加 `appcurrency`，默认 `cny`，参与 MD5 签名 |
| 中 | 网关返回绝对地址时，公网收银台配置被跳过，可能把买家引到内网地址 | 统一处理绝对 / 相对跳转，应用公网地址配置，拒绝直接返回内网收银台 URL |
| 低 | 无回归测试，配置和错误提示不完整 | 补充本机 HTTP / TLS 测试、配置校验及网关错误提示 |

以上优先级描述潜在影响，不表示已发现实际资金损失。金额、PID 和订单校验是在签名校验之后执行；旧代码的这些问题并不等于无需密钥就能伪造付款。

## 升级步骤

1. 备份现有 `plugins/epusdt/epusdt_plugin.php` 和支付通道配置。
2. 将本仓库插件文件更新到每个易支付实例的相同路径。
3. 检查通道的 API 地址、数字 PID、密钥和收银台域名。
4. 检查 `appselector`。原 TRC20-USDT 场景可留空，或明确填写 `usdt.tron`。
5. 检查 `appcurrency`。人民币计价可留空或填 `cny`；其他法币计价必须明确填写对应币种，并确保网关支持。
6. 执行语法检查及回归测试，确认站点 PHP 的 CA 证书库有效，然后用新订单检查付款跳转。

插件本身不需要数据库迁移。更新 PHP 文件时，应按站点 OPcache 配置等待重新校验或主动失效缓存。

## 协议边界

- EPay 继续使用 MD5：排除 `sign`、`sign_type`，将其余非空字段按 ASCII 字典序拼接，追加 `secret_key` 再计算 MD5。不要替换成 GMPay 的 HMAC-SHA256。
- 优先 POST 表单下单，仅在返回 `failed to parse request params` 时用同一组参数重试 GET。业务拒绝、订单冲突或网络错误不会自动改用 GET。
- 官方成功响应是 HTTP 302 和收银台地址，不是支付成功 JSON。
- `type=token.network` 优先于网关默认收款资产。设置 `alipay` 后是否进入资产选择流程取决于网关默认资产配置。
- 资产切换后的官方回调保留原 EPay 订单信息和 `type`。插件校验原易支付订单号，不把回调 `type` 当作实际到账网络。
- 网关相同订单重试要求签名字段保持不变。本次显式加入 `currency` 后，不要清空历史订单的 `ext` 再请求网关；保留缓存付款链接，已过期订单重新下单。

## 密钥轮换

官方网关会为订单保留创建时的回调签名密钥。因此，直接修改原易支付通道的 PID / 密钥，会导致旧订单回调仍使用旧密钥、插件却用新密钥验签。

轮换时新建一组网关 API Key 和易支付通道，让新订单使用新通道；保留旧通道的 PID / 密钥，直至旧订单及回调重试处理完毕。不要在普通订单扩展字段中保存明文密钥。

## 验证范围

本仓库 `tests/run.php` 覆盖 MD5 官方样例、GET / POST 回调、四位小数金额、商户隔离、异常字段、同步返回、下单参数、资产 / 法币选择、跳转地址、业务错误、GET 兼容重试、配置校验及 TLS 证书验证。

补充检查修正了旧配置缺少可选 `appswitch` 时的 PHP 警告，并在 cURL 未启用时返回明确错误。回归检查已覆盖 PHP 7.4、8.0、8.2。

`tests/integration` 还直接连接官方 v2.1.3 的 HTTP 路由和临时数据库，验证六种配置的实际下单、原订单重开和官方签名通知。测试不会运行生产扫描器，也不会修改真实订单。

测试使用临时本机服务和隔离的易支付通知替身，不会真实收款或增加商户余额。真实链上转账、第三方易支付分支和旧版本网关应在各自部署环境单独验收。
